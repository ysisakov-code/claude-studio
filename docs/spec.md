# ТЗ: «Студия» — творческая студия проектов Claude для ПК

Версия 2, 2026-10-11. Заменяет «ТЗ менеджер проектов Claude для ПК» (версия 1, на рабочем столе).
Что изменилось относительно версии 1 — в конце документа.

## 1. Цель

Локальная программа для Windows: открываю её, как творческую студию, и вижу все свои проекты, сделанные с Claude.
У каждого проекта видно, насколько он готов, где я остановился, что доработать и какие у меня мысли.
Нажимаю «Продолжить с Claude» — открывается Claude Code в папке проекта, и Claude **уже в курсе**: сам говорит, где остановились и что открыто.
Отдельный раздел «Идеи» хранит задумки будущих проектов.

Пользователь один, работа офлайн, данные на этом ПК, интерфейс на русском.
Код хранится в приватном репозитории GitHub; личные данные (база, сессии) в репозиторий не попадают.

## 2. Источники данных

Подробный формат — `docs/session-format.md`.

| Источник | Где | Что берём |
| --- | --- | --- |
| Сессии Claude Code | `~\.claude\projects\*\*.jsonl` | id, cwd старта и основной cwd, время начала/конца, первый и последний запрос, число запросов, ветка, название сессии |
| История CLI | `~\.claude\history.jsonl` | сессии, файлы которых уже удалены Claude Code |
| Агенты, скиллы | `~\.claude\agents`, `~\.claude\skills`, то же в `<проект>\.claude` | имя, описание, модель |
| Инструкции | `<проект>\CLAUDE.md` | первые строки, дата изменения |
| MCP | `<проект>\.mcp.json` | имена серверов |
| Git | папка проекта | ветка, последние коммиты, незакоммиченные изменения |
| claude.ai | вручную / импорт экспорта | ссылки на проекты и чаты |

Правила:
1. Программа **только читает** `~\.claude`.
2. Путь проекта берётся из `cwd`, а не из имени папки.
3. Незнакомые поля и битые строки пропускаются с предупреждением в логе.
4. Git учитывается, только если у папки свой репозиторий. Репозиторий на весь профиль `C:\Users\<имя>` и корень диска не считаются.
5. Скиллы плагинов (`~\.claude\plugins`) не показываются — их сотни.

## 3. Модель данных

SQLite: `%APPDATA%\ClaudeStudio\data.db`. Ручные поля сканирование не трогает.
Сессии из сканирования **не удаляются**, если Claude Code стёр файл (он чистит сессии старше 30 дней): запись получает флаг «файл удалён», кнопка «Продолжить» для неё неактивна.

**Project**: id, name, description, paths (список папок; первая — основная), stage, progress 0–100, priority (high / normal / low), tags, claude_ai_links, next_step («где остановился / с чего начать»), thoughts (мои мысли и пожелания, свободный текст), last_activity (вычисляется), created_at, updated_at.

Стадии (5 вместо 8): `idea` Идея → `design` Проектирую → `build` Делаю → `live` Работает → `paused` Пауза. Плюс `archived` (скрыт с главного экрана).

**Session**: id, project_id (может быть пустым → «Разобрать»), cwd_start, cwd_main, started_at, ended_at, first_prompt (200 симв.), last_prompt, prompt_count, git_branch, title (из Claude Code), user_title, note, entrypoint (cli / desktop), file_missing, source (jsonl / history).
Привязка: автоматически по совпадению `cwd_main` с одним из `paths` проекта (вложенные папки тоже), иначе вручную. Ручная привязка сильнее автоматической.

**Agent**: name, kind (agent / skill / mcp), scope (project / global), description, model, file_path. Глобальные можно вручную закрепить за проектами (многие-ко-многим).

**Recommendation** (доработка): project_id, text, priority, status (open / in_progress / done / rejected), source (manual / claude), created_at.

**Idea**: text, details, related_project_id, effort (small / medium / large), status (idea / planned / started). При переходе в started создаётся Project.

**StageHistory**: project_id, from_stage, to_stage, date, comment.

**ActivityLog**: project_id, date, text, source (manual / claude) — «что сделано» по итогам сессий.

## 4. Интерфейс

Окно Windows 11 (pywebview), светлая и тёмная тема, окно помнит размер и положение.

**Слева разделы:** Проекты · Идеи · Сессии · Разобрать (неразобранные сессии со счётчиком).

**Проекты** — сетка карточек (основной режим) и доска по стадиям (второй режим, перетаскивание меняет стадию и пишет в StageHistory).
Карточка: название, стадия, полоса прогресса, когда работал в последний раз, число открытых доработок, next_step. Больше 14 дней без работы — карточка приглушена с пометкой «N дней без работы».

**Экран проекта** (панель справа или отдельный экран):
- Обзор: описание, стадия, прогресс, «где остановился», доработки, мои мысли, ссылки на claude.ai, «Открыть папку».
- Кнопки: **«Продолжить с Claude»**, «Продолжить последнюю сессию», «Обсудить новую идею».
- Сессии: список, новые сверху; у каждой «Открыть эту сессию».
- Агенты: агенты, скиллы, MCP проекта и закреплённые глобальные; открыть `.md` в редакторе.
- Доработки: список с фильтром по статусу.
- Журнал: что сделано (ActivityLog), история стадий, последние коммиты.

**Идеи** — список задумок, кнопка «Обсудить с Claude» и «Сделать проектом».

Общее: поиск Ctrl+K по названиям, тегам и запросам сессий; автоматическое сканирование при запуске и кнопка «Обновить».

## 5. Связь с Claude Code

Запуск — **в Windows Terminal** (`wt.exe`, запасной вариант `cmd`), в основной папке проекта.

1. **«Продолжить с Claude»** — новая сессия `claude` со стартовой справкой о проекте: стадия, прогресс, где остановился, открытые доработки, мысли. Справка передаётся через `--append-system-prompt` и короткий первый запрос («Кратко скажи, где мы остановились, и предложи следующий шаг»). Файлы проекта не меняются.
2. **«Открыть эту сессию»** — `claude --resume <id>` в `cwd_start` этой сессии.
3. **«Обсудить новую идею»** — сессия Claude с промптом «помоги продумать идею», запуск из папки студии.
4. **MCP-сервер студии** (`studio`): инструменты `get_project`, `set_next_step`, `add_recommendation`, `update_recommendation`, `set_progress`, `log_activity`, `add_idea`. Claude в конце работы записывает итог в студию. Подключение к Claude Code — один раз, только по кнопке и с подтверждением пользователя (`claude mcp add --scope user`).
5. **«Оценить проект»** — `claude -p` читает папку, CLAUDE.md, последние коммиты и сессии, возвращает JSON: описание, стадия, прогресс, доработки. Предложение показывается пользователю и сохраняется только после подтверждения.

## 6. Стек

- Backend: Python 3.12, FastAPI, SQLModel, SQLite, миграции через PRAGMA user_version (Alembic избыточен для одной базы в .exe).
- Frontend: React + TypeScript + Vite, dnd-kit.
- Окно: pywebview, внутри локальный сервер на `127.0.0.1`, случайный порт, токен на каждый запуск.
- Сборка: PyInstaller, один `.exe`, ярлык в «Пуске».

Компоненты: `scanner/`, `storage/`, `api/`, `launcher/`, `mcp_server/`, `frontend/`.
Тесты pytest на обезличенных фикстурах; README; CLAUDE.md с архитектурой.

## 7. Этапы

После каждого этапа — показать результат, дождаться подтверждения, закоммитить и отправить на GitHub.

| Этап | Что | Готово, когда |
| --- | --- | --- |
| 0. Разведка | формат `.claude`, план | ✅ `docs/session-format.md` |
| 1. Сканер | сессии, history, агенты, скиллы, CLAUDE.md, MCP, git; тесты | `python -m scanner` выводит проекты и сессии без ошибок |
| 2. Хранилище и API ✅ | SQLite, модели, CRUD, привязка сессий | ручные данные переживают пересканирование, удалённые сессии не пропадают |
| 3. Интерфейс ✅ | сетка, доска, экран проекта, идеи, поиск, «Разобрать» | стартовые проекты видны, стадия меняется перетаскиванием |
| 4. Запуск Claude | три кнопки запуска, стартовая справка | клик открывает терминал с Claude, который знает контекст |
| 5. MCP студии | сервер `studio`, кнопка подключения | Claude из сессии записывает «где остановился» и доработку |
| 6. Оценка проекта | «Оценить проект» через `claude -p` | предложение показано и сохраняется по подтверждению |
| 7. Сборка | `.exe`, иконка, ярлык | запускается на Windows без Python |

Критерии: скан 50 проектов и 1000 сессий меньше 5 с; ничего не пишется в `~\.claude`, кроме явной кнопки подключения MCP; сеть не используется (кроме GitHub для кода); битый файл сессии → предупреждение, не падение.

## Изменения относительно версии 1

- Концепция «Студии»: карточки с прогрессом основным режимом, доска вторым.
- 5 стадий вместо 8.
- Поля «мои мысли» и журнал «что сделано».
- «Продолжить с Claude» передаёт Claude справку о проекте.
- MCP-сервер студии: Claude сам обновляет карточку.
- «Оценить проект» перенесено из «позже» в этап 6.
- Сессии не удаляются из базы, когда Claude Code стирает файл.
- Проект может иметь несколько папок; ручная привязка сессий.
- Скиллы плагинов не показываются; git учитывается только у собственного репозитория папки.
- Хранилище переименовано в `%APPDATA%\ClaudeStudio`.
- Код в приватном репозитории GitHub.
